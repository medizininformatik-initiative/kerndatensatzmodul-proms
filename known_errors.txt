# Known Validation Errors - MII PRO Implementation Guide

## SDC STU4 / FHIR R4.0.1 Compatibility Issues

### 1. itemWeight Property URI Error
**Error**: `Unknown CodeSystem Property 'http://hl7.org/fhir/concept-properties/itemWeight'. If you are creating your own property, do not create it in the HL7 namespace`

**Status**: Will be fixed in upcoming FHIR version
**Details**: 
- The `itemWeight` property is part of SDC STU4 specification
- Currently not recognized by FHIR R4.0.1 validator
- This is a forward-compatibility issue with SDC STU4 on FHIR R4
- The URI `http://hl7.org/fhir/concept-properties/itemWeight` is correct per SDC STU4

**Impact**: 
- Validation errors but functionality should work in SDC STU4 compliant servers
- Score calculations using `.weight().sum()` FHIRPath expressions depend on this property

**References**:
- SDC STU4 Specification: [Calculated Expressions](http://hl7.org/fhir/uv/sdc/calculation.html)
- This replaces the deprecated `ordinalValue` extension from SDC STU3

### 2. ordinalValue Deprecation Warnings
**Warning**: `The extension http://hl7.org/fhir/StructureDefinition/ordinalValue|5.2.0 is deprecated with the note Replaced by itemWeight`

**Status**: Expected during transition period
**Details**:
- PHQ-9 still uses deprecated `ordinalValue` extensions
- BDI-II uses new `itemWeight` properties
- Both approaches coexist during SDC STU3 → STU4 migration

**Action**: Continue migration to `itemWeight` for consistency

### 3. SDC Constraint Violation: versionAlgorithm Required
**Error**: `Constraint failed: sdc-2: 'If version is present, versionAlgorithm must be present.'`

**Status**: **HIGH PRIORITY** - Needs questionnaire versioning strategy decision
**Details**:
- SDC STU4 requires `versionAlgorithm` when questionnaire has a version
- Quick fix: Add `* versionAlgorithm = #date` to questionnaires
- **Strategic Issue**: Need comprehensive versioning strategy for all questionnaires across the IG

**Impact**: 
- Affects questionnaire governance and lifecycle management
- Critical for balloting version and future updates
- Impacts how questionnaire changes are tracked and validated

**Action Required**: 
1. **Immediate**: Add `versionAlgorithm = #semver` to questionnaires (not #date)
2. **Strategic**: Implement hybrid versioning strategy:
   - **CalVer** for IG, Profiles, Extensions (follows MII standard)
   - **SemVer** for Questionnaires, CodeSystems, ValueSets (content-driven versioning)
3. **Balloting**: Added to balloting questions for community feedback

## Expected Resolution Timeline
These errors will be resolved when:
1. FHIR R5 or updated R4 validator recognizes SDC STU4 itemWeight properties
2. Full migration from ordinalValue to itemWeight is complete across all questionnaires
3. SDC STU4 specification reaches final publication status
4. **Questionnaire versioning strategy implemented across all questionnaires**

## Workaround for Current Development
- Use `--allow-deprecated` flag with validators if available
- Focus on functional testing with SDC STU4 compatible servers
- Document these as "expected errors" in balloting materials
- **Prioritize questionnaire versioning strategy development**
